# 设计原则与视觉层级 playbook

> 好设计先讲清楚，再讲好看的。本 playbook 给一套可操作的设计原则与层级构建方法。

## 1. 四大基础原则（CRAP）

```
C 对比 (Contrast)    — 用大小/色/粗细区分主次，杜绝"差不多"
R 重复 (Repetition)  — 同类元素统一，建立节奏与识别
A 对齐 (Alignment)   — 一切元素都有对齐基准，拒绝随意摆放
P 亲近 (Proximity)   — 相关信息靠近，无关信息拉开
```

## 2. 构建视觉层级（决策树）

```
Q1 用户第一眼该看到什么？  → 最大字号 / 最强对比 / 唯一彩色
Q2 次要信息有哪些？        → 降一级字号，弱化色彩
Q3 操作入口在哪？          → 按钮/CTA 视觉权重最高且唯一
Q4 装饰是否干扰信息？      → 是则删，装饰服务内容而非反过来
```

**经验法则**：一屏只服务一个核心目标，层级越清晰转化越高。

### 2.1 层级的量化判据（别只靠眼睛）

"看着有层级"不可复核。三条可以直接算的判据：

**判据 1 — 相邻层级字号比 ≥1.2 才构成层级**

```bash
python3 -c "
sc=[12,14,16,20,24,32,40,48]
print('相邻比:', [round(sc[i+1]/sc[i],2) for i in range(len(sc)-1)])
print('比值<1.2（不可作层级区分）:', [(sc[i],sc[i+1]) for i in range(len(sc)-1) if sc[i+1]/sc[i]<1.2])
"
# 相邻比: [1.17, 1.14, 1.25, 1.2, 1.33, 1.25, 1.2]
# 比值<1.2（不可作层级区分）: [(12, 14), (14, 16)]
```

读法：**阶梯低端的相邻两档（12↔14、14↔16）比值不足 1.2，不能用来表达主次**——
它们只是"同级微调"。caption 与正文的区分必须靠**颜色/字重/位置**，靠字号一定糊。
要做真层级，至少跨一档（16 → 20 或 16 → 24）。

**判据 2 — 正文行长（measure）落在可读区间**

```bash
python3 -c "
for fs in (14,16,18,20):
    print(f'{fs}px: 西文 45-75ch = {round(fs*0.5*45)}-{round(fs*0.5*75)}px / 中文 25-40 字 = {fs*25}-{fs*40}px')
"
# 16px: 西文 45-75ch = 360-600px / 中文 25-40 字 = 400-640px
```

超上限（长行）→ 回行时找不到下一行起点；低于下限（窄行）→ 断词频繁、右侧参差。
容器宽度定不下来时，就用这组数反推 `max-width`。

**判据 3 — 强调元素唯一性**：一屏内"最高视觉权重"的元素（最大字号 / 唯一饱和色 / 唯一实心按钮）
**必须只有一个**。数出来大于 1，层级就已经失效——这是自查最快的一条。

## 3. 留白与栅格

- 留白不是空，是信息的呼吸；密集堆砌降低可读性。
- 用 8px 栅格对齐间距，间距也有层级（4/8/16/24/32）。
- 移动端单列优先，桌面端可多列但保持对齐基准。

### 3.1 间距阶梯（可运行 + 判读规则）

间距和字号一样要成阶梯，否则每处 padding 都是随手拍的数：

```bash
python3 -c "
s=[4,8,12,16,24,32,48,64]
print('阶梯:', s)
print('全为 4 的倍数:', all(x%4==0 for x in s))
print('相邻比:', [round(s[i+1]/s[i],2) for i in range(len(s)-1)])
"
# 阶梯: [4, 8, 12, 16, 24, 32, 48, 64]
# 全为 4 的倍数: True
# 相邻比: [2.0, 1.5, 1.33, 1.5, 1.33, 1.5, 1.33]
```

判读规则（这套阶梯该怎么用）：

| 场景 | 取值 | 理由 |
|------|------|------|
| 图标与文字、标签与输入框 | 4 / 8 | 紧邻关系，靠"亲近"表达绑定 |
| 卡片内边距、列表项间距 | 16 / 24 | 内容区呼吸，最常用的两档 |
| 区块（section）之间 | 32 / 48 / 64 | 跨语义分组，必须明显大于组内间距 |

**核心纪律：组内间距必须小于组间间距。** 这是"亲近原则"的可量化形式——
若卡片内元素间距 24 而卡片之间也是 24，视觉上会读成一整片，分组消失。
自查方式：任取一个分组，量出组内最大间距与组外最小间距，后者至少是前者的 **1.5 倍**。

注意阶梯**不是纯几何倍增**（否则是 4/8/16/32/64，中间缺 12/24/48 这些高频档），
所以保留 1.33 与 1.5 的混合步进——够用又不失克制。

## 4. 交付前检查清单

- [ ] 一眼能看出主次（层级成立）
- [ ] 同类元素对齐且统一（CRAP 达标）
- [ ] 正文可读性（字号/行高/对比度足够）
- [ ] 装饰不干扰信息
- [ ] 跨物料视觉一致
- [ ] 最高视觉权重元素**只有一个**（判据 3 数得出来）
- [ ] 正文行长在可读区间（西文 45–75ch / 中文 25–40 字）
- [ ] 组内间距 < 组间间距（后者 ≥1.5 倍），分组关系立得住
- [ ] 所有间距取自阶梯（4/8/12/16/24/32/48/64），无随手拍的中间值

## 5. 常见坑

- **平均用力**：所有元素一样大一样重，没有焦点。
- **装饰过度**：渐变/阴影堆砌，信息被淹没。
- **忽略对比度**：浅灰字配白底，可读性崩塌（也踩无障碍红线）。
- **无系统**：每屏一套规则，品牌感全无。
- **相邻档做层级**：用 14px 和 16px 表达主次（比值 1.14），放到真实页面上完全读不出差别——
  见判据 1，做层级至少跨一档。
- **等间距铺满**：所有间距都用同一个值（常见是 16），CRAP 的"亲近"直接失效，
  信息成一整片；分组必须靠间距差异，不是靠分割线补救。
- **只在设计稿里验层级**：设计稿里文案都是理想长度，真实数据下标题换行、数字变长，
  层级关系会翻转——用**最长/最短的真实内容**各过一遍再交付。

## 6. 相关子技能与层次边界

本 playbook（L2）给出**跨子技能通用**的设计原则与视觉层级方法；具体落地由各 L3 子技能承担：

- [skills/brand-designer/](../skills/brand-designer/SKILL.md) — 品牌识别与一致性检查直接套用 CRAP 与层级决策树（§1/§2）
- [skills/illustrator/](../skills/illustrator/SKILL.md) — 构图原则（三分法/视觉引导线）复用本 playbook §1 对齐/亲近原则
- [skills/poster-design-generation/](../skills/poster-design-generation/SKILL.md) — 海报视觉层级与留白节奏对应本 playbook §2/§3
- [skills/web-typography/](../skills/web-typography/SKILL.md) — 正文可读性（字号/行高/对比度）对应本 playbook §3 留白与对比度纪律
- 兄弟 playbook：[references/brand-typography-system.md](brand-typography-system.md) — 字体系统搭建是层级方法在排版维度的具体化

**层次边界**：L2 讲"好设计长什么样"的通用判据；具体配色方案、插画风格、字体选型等交给对应 L3 子技能。

**跨仓边界**：无障碍层面的系统性审计（键盘/读屏/WCAG 全量）→ `accessibility-engineer`；
UI 组件与交互态规范 → `design-studio`；动效时序与曲线 → `animation-engineer`。
本 playbook 只负责**静态视觉的层级与空间判据**。
