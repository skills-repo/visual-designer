# 品牌与字体系统 playbook

> 品牌不是 Logo，是一套让人一眼认出的视觉语言。本 playbook 给品牌资产清单与字体系统搭建方法。

## 1. 品牌视觉资产清单

```
□ 主色 + 辅助色（含色值/使用场景）
□ 字体组合（标题体 + 正文体，含替代方案）
□ Logo 与安全距离
□ 图形/图标语言
□ 图片/插画风格基调
□ 语气与排版基调（严谨/亲和/前卫）
```

**原则**：品牌规范先定义"能用的"和"禁止的"，下游才不会跑偏。

## 2. 字体系统搭建

```
1. 选标题体    — 有个性但不牺牲可读性（衬线显权威/无衬线显现代）
2. 选正文体    — 优先屏幕可读性，行高 1.5 左右
3. 定层级      — H1/H2/H3/正文/注释 的字号与字重映射
4. 定替代      — 目标字体不可用时回退到系统字体
5. 定字距      — 大标题可收紧字距，正文保持默认
```

**铁律**：正文永远优先可读性；展示字体只用于少量标题，别铺满正文。

### 2.1 模数字号阶梯速算（可运行）

字号别一个个"看着定"。先选模数比，用一条命令把整套阶梯算出来，再做取整：

```bash
python3 -c "
r=1.25; base=16
for s in range(-2,6): print(f'step {s:+d}: {round(base*r**s,1)}px')
"
# step -2: 10.2px  step -1: 12.8px  step +0: 16.0px  step +1: 20.0px
# step +2: 25.0px  step +3: 31.2px  step +4: 39.1px  step +5: 48.8px
```

模数比三档选型：

| 比率 | 名称 | 相邻层级观感 | 适用 |
|------|------|--------------|------|
| 1.2 | Minor Third | 温和、层级密 | 信息密集的后台 / 文档站，档位多 |
| 1.25 | Major Third | 平衡（默认起点） | 大多数产品站、App |
| 1.333 | Perfect Fourth | 对比强、气势足 | 营销落地页 / 海报，档位少 |

**关键增量（几乎所有教程不写）：纯几何阶梯在小字号端必须手工夹紧。** 上面 `step -2` 算出 10.2px、`step -1` 算出 12.8px，都低于屏幕正文可读下限。落地规则：

1. 小端夹紧：`≤12px` 一律取 **12px**（仅用于 caption/角标），`12.8px` 上抬到 **14px**（次要正文下限）
2. 大端对齐栅格：标题档取整到 **4 的倍数**（25.0→24、31.2→32、39.1→40、48.8→48），才能落进 8px 栅格
3. 夹紧后得到落地阶梯 **12 / 14 / 16 / 20 / 24 / 32 / 40 / 48**（与社区主流 type scale 一致，见文末来源）

行高按档位分离：标题 **1.2**（tight），正文 **1.5**（normal），中文正文可放宽到 **1.6–1.75**（汉字字面框满、视觉更挤）。

### 2.2 字体选型决策树

```
Q1 这段字是"读"的还是"看"的？
   └ 读（正文/表格/表单）→ 屏幕优化无衬线或屏幕衬线；禁用展示体、禁用细字重(<400)
   └ 看（大标题/海报/Logo）→ 可上展示体、可变字体高字重

Q2 有中文吗？
   └ 有 → 先定中文字体再配西文（反过来必然错位）；确认字重档位是否真的存在
   │      （多数中文字体只有 Regular/Bold 两档，Medium/Semibold 会被浏览器合成 → faux bold）
   └ 只有西文 → 可用可变字体做连续字重（font-weight: 650 这种非整档值）

Q3 需要几种字体？
   └ 1 种（同族多字重）→ 默认答案，最安全
   └ 2 种（标题体 + 正文体）→ 需要品牌区分度时
   └ ≥3 种 → 除非有强理由，否则视为设计缺陷（见 §5 坑）

Q4 交付到 Web？
   └ 是 → 只发 .woff2（Brotli 压缩、支持面广）；.ttf/.otf 是桌面格式不上 Web
   └ 否（印刷/PPT）→ 确认对方机器有字体，否则转曲或嵌入
```

## 3. 色彩使用纪律

- 主色用于品牌识别与关键操作，不滥用。
- 功能性色（成功/警告/错误）与品牌色分开，避免歧义。
- 文本与背景对比度满足 WCAG AA（正文 ≥4.5:1）。

### 3.1 对比度速算与判据（可运行）

"对比度要达标"是空话，定色时就该把数算出来。零依赖速算（WCAG 2.2 相对亮度公式）：

```bash
python3 -c "
def L(h):
 h=h.lstrip('#'); c=[int(h[i:i+2],16)/255 for i in (0,2,4)]
 c=[x/12.92 if x<=0.03928 else ((x+0.055)/1.055)**2.4 for x in c]
 return 0.2126*c[0]+0.7152*c[1]+0.0722*c[2]
a,b=L('767676'),L('ffffff'); print(round((max(a,b)+0.05)/(min(a,b)+0.05),2))
"
# 4.54  → #767676 是白底上"刚好过 AA 正文"的最深浅灰，比它浅一档就不合规
```

判据表（**同一个色值在不同字号下结论不同**，这是最常被忽略的一点）：

| 用途 | AA 门槛 | AAA 门槛 |
|------|---------|----------|
| 正文（<18.66px 常规 / <24px 粗体） | 4.5:1 | 7.0:1 |
| 大字（≥18.66px 常规 / ≥24px 粗体） | 3.0:1 | 4.5:1 |
| 图标 / 输入框边框等非文本 | 3.0:1 | — |

不达标的处置顺序（**先动明度，不要先动色相**）：

1. 降/升前景色明度（品牌色相保持不变）→ 复算
2. 仍不过 → 加深背景或加半透明遮罩层
3. 仍不过 → 该色降级为"装饰色/大字色"，正文换中性色（品牌主色不是必须能当正文色）
4. 绝不用"加阴影/描边"糊过去 —— 对比度算的是前景与背景本身

**跨仓边界**：本速算是设计定色时的**单点手算**；要做整套色板/页面的**系统性 WCAG 审计**，走
`accessibility-engineer/scripts/contrast_check.py`（支持 `--json` 与 `--strict` 作 CI 门禁）：

```bash
python3 accessibility-engineer/scripts/contrast_check.py "#767676" "#ffffff"
# 对比度: 4.54:1  正文 AA(4.5): PASS  AAA(7.0): FAIL  大字 AA(3.0): PASS
```

## 4. 系统交付前检查清单

- [ ] 色彩/字体/Logo 规范成文且含禁用项
- [ ] 字体层级映射明确（含回退方案）
- [ ] 对比度达标（含无障碍）
- [ ] 跨物料抽样一致
- [ ] 字号阶梯有明确模数比与落地取整值（小端已夹紧 ≥12px，标题档为 4 的倍数）
- [ ] 每个用到的字重在**目标字体里真实存在**（不是浏览器合成的 faux bold）
- [ ] 品牌主色已复算对比度，明确它「能当正文色」还是「只能当大字/装饰色」

## 5. 常见坑

- **字体过多**：一套物料用 4 种以上字体，杂乱无章。
- **忽视回退**：目标字体加载失败，排版崩坏。
- **色彩滥用**：主色铺满，失去强调作用。
- **无规范**：每次设计重新发明，品牌感丢失。
- **faux bold / faux italic**：给只有 Regular+Bold 的中文字体指定 `font-weight: 500/600`，
  浏览器合成加粗，笔画糊成一团 —— 先确认字体真实字重档位，再定层级映射。
- **只审代码不看渲染页**：字号/行高在 CSS 里"看着对"，真实内容长度下才暴露孤字（widow）、
  截断、中英混排跳动 —— 规范落地后必须用**真实长文本**回看渲染结果。
- **em 层层继承漂移**：嵌套容器都用 `em` 定字号，三层套下来实际字号已不在阶梯上 —— 
  字号用 `rem`（锚定根值），只有需要跟随父级的场合（如图标随文字）才用 `em`。

## 6. 相关子技能与层次边界

本 playbook（L2）沉淀**跨子技能共享**的品牌与字体系统搭建方法；具体执行落到各 L3 子技能：

- [skills/brand-designer/](../skills/brand-designer/SKILL.md) — 品牌视觉资产清单与字体组合规范直接喂给品牌系统搭建（L2 §1/§2 → L3 品牌手册/字体层级映射）
- [skills/web-typography/](../skills/web-typography/SKILL.md) — 字体层级映射（H1-H6）与回退方案对应本 playbook §2 第 4-5 步
- [skills/poster-design-generation/](../skills/poster-design-generation/SKILL.md) — 海报主标题字号与字距收紧复用本 playbook §2 字距铁律
- 兄弟 playbook：[references/design-principles.md](design-principles.md) — 四大基础原则（CRAP）是本 playbook 色彩/字体纪律的上层依据

**层次边界**：L2 只讲"品牌字体系统怎么搭"的通用方法；具体某品牌的色值/字体选型、Web 流体字号实现等交给对应 L3 子技能。

**跨仓边界**：系统性 WCAG 审计与无障碍整改 → `accessibility-engineer`；
Token 工程化（命名/多主题/CI 校验） → `figma-master` 的 `references/design-token-strategy.md`；
UI 组件层规范 → `design-studio`。本 playbook 只负责**视觉侧的系统定义与设计期速算**。
